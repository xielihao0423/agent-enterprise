## 1. 需求与目标

### 一句话需求
基于火山引擎 veadk-python 框架开发一个企业级 Agent 平台，使小团队用户能够创建和管理多个 AI Agent 并配置角色文件、模型、Skill、知识库与长期记忆，同时通过飞书机器人接入实现单聊/群聊对话，采用单租户私有化部署且凭据加密存储。

### 背景
- 企业内部需要统一的 Agent 管理平台，将 AI Agent 能力系统化纳管，避免散落各处的人工配置和脚本。
- 火山引擎开源的 veadk-python 框架已提供 Agent、Runner、Session、Memory、KnowledgeBase、Skills、FeishuChannelExtension、Tracing 等核心能力，可直接复用以避免重复造轮子。
- 当前缺少一个面向小团队的、私有化部署的、前后端一体的管理平台来编排这些能力。
- 触发来源：企业内部 AI 能力平台化建设需求。

### 目标与成功标准
- 目标：交付一个单租户私有化部署的 Agent 平台，支持多 Agent 创建与管理、角色文件配置、模型/Skill/知识库/长期记忆配置、飞书机器人接入和对话 Session 管理。
- 目标：前端管理台可完成 Agent 全生命周期配置，对话界面可进行多会话交互。
- 成功标准：可创建多个 Agent 并分别完成四类角色文件、模型、Skill、知识库与长期记忆配置；飞书机器人可完成单聊/群聊消息接入并与平台 Session 正确映射。

## 2. 范围与业务规则

### 范围
- **做什么：**
  1. **多 Agent 管理**：创建、编辑、启停、删除、复制 Agent；支持 Agent 列表查看与基本属性管理。
  2. **Agent 角色文件配置**：配置与版本化维护 Agent.md、USER.md、IDENTITY.md、SOUL.md 四类角色文件，并注入运行时上下文。
  3. **模型配置**：支持火山引擎 ARK（豆包系列）和 OpenAI（GPT 系列）两类模型供应商接入；支持凭据管理、默认模型与推理档位设置、按 Agent 选择模型。
  4. **Skill 配置**：支持 Skill 安装、绑定/解绑、启停与版本管理，Agent 可按需启用已绑定的 Skill。
  5. **知识库配置**：支持知识库创建、文档上传/解析/索引、按 Agent 绑定与检索参数配置。
  6. **长期记忆配置**：支持记忆开关、作用域（Agent/用户/会话）、写入策略、检索与清理。
  7. **飞书机器人接入**：支持机器人创建/绑定、Webhook 或长连接接入、文本与文件附件消息收发、群聊/单聊会话映射。
  8. **对话与 Session 管理**：支持多会话、上下文隔离、历史消息查看、中断/续跑、附件与状态查询。
  9. **前后端**：后端提供 REST API 与鉴权、数据持久化、运行时编排；前端提供管理台与对话界面。

- **不做什么：**
  - 不做多租户隔离与 SaaS 计费/配额体系（首期单租户私有化）。
  - 不做模型微调/训练能力。
  - 不做 Skill 的在线开发/编辑器（仅做安装、绑定/解绑、启停与版本管理）。
  - 不做知识库的在线标注/分块预览编辑（仅做上传/解析/索引/检索参数配置）。
  - 不做飞书卡片消息、交互按钮回调、富文本消息（首期仅文本+附件）。
  - 不做 A/B 测试、灰度发布、自动评测等运营能力。
  - 不做移动端 App（首期仅 Web 前端）。

### 核心业务规则
- **Agent 隔离规则**：每个 Agent 独立配置角色文件、模型、Skill、知识库与记忆参数；不同 Agent 之间配置隔离，运行时上下文互不干扰。
- **角色文件规则**：四类角色文件（Agent.md / USER.md / IDENTITY.md / SOUL.md）支持版本化维护，运行时按当前生效版本注入 Agent 上下文；修改后新版本生效，历史版本可回溯查看。
- **模型选择规则**：平台支持配置多个模型实例（ARK + OpenAI），每个 Agent 绑定一个默认模型和推理档位；模型凭据加密存储，前端不返回明文。
- **Skill 规则**：Skill 安装到平台级 Skill 库后，Agent 可按需绑定/解绑；绑定后可按 Agent 级别启停；Skill 版本更新后可选择是否升级。
- **知识库规则**：知识库为平台级资源，可被多个 Agent 绑定；每个绑定关系可独立配置检索参数（如 Top-K、相似度阈值）；文档上传后自动解析和索引。
- **长期记忆规则**：记忆作用域分为 Agent 级、用户级、会话级三级；写入策略支持自动写入和手动写入；记忆可按作用域检索和清理。
- **飞书机器人规则**：一个 Agent 可绑定一个飞书机器人；飞书单聊映射为平台中该用户的独立 Session，群聊映射为群维度的共享 Session；消息收发支持文本和文件附件。
- **Session 规则**：一个 Agent 可有多个会话；会话间上下文隔离；支持查看历史消息、中断当前执行和续跑；会话状态可查询。
- **鉴权规则**：单租户私有化部署，采用统一的用户认证机制（推断：基于用户名/密码或对接企业 SSO，具体方案待技术设计）；所有 API 需认证后访问。

### 边界与异常
- **凭据安全**：模型 API Key、飞书 App Secret 等敏感凭据加密存储，API 响应和前端展示均脱敏。
- **运行时异常**：模型调用失败、Skill 执行异常、知识库检索超时等场景需有明确错误反馈和降级策略。
- **飞书连接异常**：Webhook/长连接断开时需自动重连并记录告警日志。
- **Session 中断恢复**：Agent 执行被中断后，会话状态保留，用户可基于已有上下文续跑。
- **操作审计**：Agent 创建/编辑/删除、模型配置变更、Skill 绑定/解绑等关键操作记录审计日志。
- **可观测性**：记录请求日志、Agent 执行轨迹、模型 Token 用量与错误监控。

## 3. 用户与场景（概要）

- **目标用户**：企业小团队（<50 人），包括平台管理员（负责 Agent 平台配置与运维）和终端用户（通过飞书或前端对话界面与 Agent 交互）。
- **使用场景：**
  1. 管理员在管理台创建 Agent，配置角色文件、绑定模型/Skill/知识库/记忆参数，部署飞书机器人。
  2. 终端用户通过飞书单聊或群聊向 Agent 发送消息，获取 AI 回复，支持多轮对话和文件附件。
  3. 管理员在管理台查看 Agent 对话历史、Session 状态、执行轨迹和 Token 用量。
  4. 终端用户通过前端对话界面与指定 Agent 进行多会话交互。
- **关键路径概要：**
  1. 管理员创建 Agent → 配置角色文件与模型 → 绑定 Skill/知识库/记忆 → 绑定飞书机器人 → Agent 上线。
  2. 终端用户飞书消息 → 飞书机器人接收 → 映射到平台 Session → Agent Runner 执行 → 回复消息到飞书。

## 5. 交接摘要

### PRD / Spec 设计节点应消费的结论
- 部署形态已确定为单租户私有化，无需设计多租户隔离、计费和配额体系。
- 用户规模为小团队（<50 人，<10 Agent），架构设计以轻量和快速交付为主，不需要分布式和高并发方案。
- 模型供应商首期接入火山引擎 ARK 和 OpenAI，Spec 需覆盖这两类供应商的配置流程和凭据管理。
- 飞书机器人首期范围为文本+附件+会话管理，不需设计卡片消息和交互按钮回调。
- veadk-python 已提供 Agent/Runner/Session/Memory/KnowledgeBase/Skills/FeishuChannelExtension 等核心能力，平台层应封装而非重写。

### 关键约束
- 基于 veadk-python 实现，避免重复造轮子。
- 敏感凭据加密存储，操作审计。
- 模型/Skill/知识库/机器人适配器采用插件/接口化设计，可扩展。
- 请求日志、Agent 执行轨迹、模型 Token 用量与错误监控。
- 关键链路有自动化测试与部署文档。
